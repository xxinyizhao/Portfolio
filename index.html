CASE FILE 02 · PCB DESIGN

Smart Debugging Board V1

September 2025 — December 2025
PCB Design (Altium, KiCad)Power Electronics (Buck/Boost, LDO, PMIC)OscilloscopeDMM
DESCRIPTION
  • Centralized interface for debugging and testing the team’s 24 V low-voltage system boards.
  • Consolidates the on-car USB, CAN, J-Link, and other debugging connectors into one off-board micro-HDMI connector.
  • Supports laptop USB-C, banana-jack, and barrel-jack inputs. With laptop power, a TPS61376 boost converter steps the 5 V USB input up to 24 V.
  • This project taught me the complete PCB design process, from component research and selection through schematic capture and layout.
BLOCK DIAGRAMS + LOGIC

Overall diagram

Power supply and protection

  • Fuse_EN: Uses MOSFETs to drive the enable pins of every e-fuse and connects to VCC_Logic through the test PCB.
  • VCC_Logic: A low-power 5 V logic rail supplied to the target PCB so higher-power rails must be explicitly enabled.
  • Fuse_EN and VCC_Logic are shorted together by default on the test board, enabling the fuses unless intentionally overridden.
  • Two 50 kΩ resistors are placed physically far apart to limit current through VCC_Logic and reduce damage risk during a short.
  • 24V_PJ and 24V_BP are diode-ORed external 24 V inputs, allowing only the higher-voltage source to power the HDMI interface.
ERROR ANALYSIS

  1. Preventing excessive laptop current draw

    If connected to the full vehicle harness, the board could draw more current than a laptop USB-C port should supply.

    Solution: Primary and secondary e-fuses provide overcurrent and reverse-current protection. Fuse_EN controls all e-fuses through MOSFET level shifting, while VCC_Logic forces the target board to explicitly enable high-power rails. This prevents laptop back-driving and overload.

  2. Protecting the micro-HDMI connector

    The HDMI pins are rated for only 0.5 A, so an external supply could otherwise force damaging current through the connector.

    Solution: Upstream e-fuses enforce current limits, and high-power inputs remain isolated until explicitly enabled.

  3. Reducing user-error risks

    Users may connect multiple supplies, reverse the banana jacks, or physically short components.

    Solution: The design uses diode OR-ing, reverse-polarity protection, reviewed connector spacing, and a planned enclosure that physically constrains misuse.

  4. Maintaining USB Full-Speed integrity

    Routing 12 Mbps USB through several connectors, cables, and another PCB can degrade the signal.

    Solution: I sourced a repeater that explicitly buffers USB Full Speed rather than transparently passing FS/LS signals.

CASE FILE 06 · PCB DESIGN

Pseudo Segment Testing Board

December 2024
PCB Design (Altium, KiCad)OscilloscopePower SupplyDMM
DESCRIPTION

During my first year on the UBC Formula Electric design team, I designed a pseudo segment testing board in Altium Designer.

  • Supports validation of Battery Management System algorithms using physical 18650 lithium-ion cells. It interfaces directly with the team’s BMS module boards for cell-voltage monitoring and active balancing, and with thermistor boards that provide battery-cell temperature feedback.
  • Tests up to 14 cells. Each cell is routed through an independent switch that enables or isolates its connection to the BMS through designated mounting holes.
  • Includes adjustable potentiometers that simulate temperature variations at the thermistor inputs, enabling verification of thermal-response and protection algorithms.
  • Receives power through two Molex connectors for stable operation and compatibility with the existing BMS hardware.
REFLECTIONS
  • I gained a deeper understanding of the battery management system and how it functioned in our car through designing and testing this board.
  • I learned the importance of carefully checking footprints and 3D models after we ordered a board with misaligned battery clips. Because the clips were through-hole and both pins shared the same net, we were able to bend one pin and fit each clip in the correct orientation.

CASE FILE 05 · FPGA DIGITAL DESIGN

ARC4 Decryption Circuit

November 2025
VerilogFPGA (ModelSim, Quartus)
DESCRIPTION
  • Implemented the complete ARC4 stream cipher in hardware on the DE1-SoC FPGA, including state initialization, key scheduling, pseudo-random generation, and decryption.
  • Designed a memory-centric architecture using multiple M10K on-chip RAM blocks for state, ciphertext, and plaintext storage.
  • Built a brute-force key-cracking engine that searches the entire 24-bit key space and validates plaintext using ASCII ranges.
  • Developed a parallel “doublecrack” accelerator with two cracking cores working on separate halves of the key space.
  • Used an active-OR arbitration mechanism to safely manage shared plaintext memory between the two parallel cores.
  • Achieved a significantly faster cracking implementation than the baseline single-core design.
  • Verified functionality using ModelSim RTL and post-synthesis simulation, along with Quartus’ In-System Memory Editor.
  • Strengthened my SystemVerilog, FPGA design, memory-system, hardware-microprotocol, and parallel digital-architecture skills.
